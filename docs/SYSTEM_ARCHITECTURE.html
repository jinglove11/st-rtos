调度算法细节

优先级抢占

  • 0 最高,31 最低(idle 在 31)
  • O(1) 位图:ready_bitmap[4] × 32 = 128 级,用 __builtin_ctz
  • 每优先级一条双向链表,插入/删除 O(1)
  • RT band: prio ≤ 15(KERN_RT_PRIORITY_MAX)

时间片

  • 默认 KERN_DEFAULT_TIME_SLICE=5 tick
  • SysTick 每 tick 把 time_slice--
  • 到 0 → need_resched=1 → 触发 PendSV
  • 支持 3 策略:SCHED_FIFO(不轮转) / SCHED_RR / SCHED_NORMAL

7IPC 机制

三种 IPC 原语,共用 wait_queue 阻塞唤醒基础设施。

Endpoint C/S 多对一

多客户端 → 单服务端。客户端 send 阻塞等 reply,服务端 recv 后 reply 唤醒客户端。 带容量 max_pending 的环形缓冲,3 个等待队列(recv/send/reply)。支持 cap 转移(send_caps/recv_caps)。

Channel P2P 一对一

两个对等任务双向通信 + 共享内存(shm[256] 字节)。适合 driver↔client 紧耦合场景。
与 endpoint 并列,共用 ipc_transfer。

8Capability 安全模型

每个内核对象(semaphore/endpoint/task/mmio…)都由 capability 句柄保护。用户任务必须持有对应权限的 cap 才能 syscall 访问。 cap 句柄 = (generation << 7) | slot,generation 防 stale 重用。

CMake — RP2350 (主路径)

  • 输出: .elf / .bin / .hex
